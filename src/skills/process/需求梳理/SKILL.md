# 需求梳理 —— 开发前置硬流程

> 🔴 这是柳柳亲定 d-006 的落地：**需求梳理 → 确立 → 原型先行 → 柳柳验收 → 才编码**。需求没确立，不动手编码；编码中需求要变，回改需求，不偷偷改代码。
> 治「每次改一点点就重构」的毛病（2026-10-21 立）。

## 🔴🔴🔴 铁律（最高）

1. **需求未确立，禁止修改正式代码**。允许：提问、分析、做草稿原型、讨论。禁止：改正式代码。
2. **原型未获柳柳验收，禁止进入开发**。验收是柳柳一眼定夺（d-005：恢复/需求的成败尺子 = 柳柳验收，不是哥哥自查）。
3. **编码中需求要变 → 回改需求，不偷偷改代码**。
4. **不自行扩大范围**：开发只按已批准规格实现，不顺手加需求外的功能。
5. **批准记版本**：柳柳批准的是「具体版本的需求+原型」，不是一句无法追溯的「好」。

## 🎯 六阶段状态机（每步都有进入条件/必需产出/禁止动作）

设计图（2026-10-21 柳柳验收）：
![需求梳理六阶段设计图](https://shxfosnnaoxzscrhvkat.supabase.co/storage/v1/object/public/files/a20b8fa0-e3de-408e-8381-38b59a8a7ec2.png)

```
需求收集 → 需求确立 → 原型生成 → ★确认门禁 → 开发实现 → 验收交付
```

### ① 需求收集
- **进入条件**：柳柳提出一个想法/需求/痛点。
- **必需产出**：需求草案、用户场景、已知约束、关键歧义已识别。
- **动作**：提问澄清、拆场景、找痛点、问边界。
- **禁止**：不做任何代码改动。

### ② 需求确立
- **进入条件**：①的草案完成、歧义已识别。
- **必需产出**：需求规格（范围、行为规则、边界、验收标准、未决项）。未决项若影响方案，必须由柳柳明确处理，否则不进下一阶段。
- **动作**：把模糊想法定成可验收规格。
- **禁止**：需求未明不写代码；不让哥哥把猜测悄悄写成用户需求。

### ③ 原型生成
- **进入条件**：②的规格确立。
- **必需产出**：可视化原型，覆盖所有关键用户场景。形式按需求类型：
  - 界面型：能直接看的页面原型，关键交互能点通。
  - 流程型：状态图/流程图 + 正常/异常路径。
  - 数据型：字段样例、数据关系、读写行为、边界案例。
  - 混合型：组合，用一份主规格串起来。
- **默认交付**：界面型需求③默认出原型（用 agnes 生图），不是可省略项。
- **禁止**：原型 ≠ 正式实现；不要把能看到的原型当成后端/权限/存储已完成。

### ④ 确认门禁 ★（真正的闸门）
- **进入条件**：③的原型覆盖关键场景。
- **动作**：把原型 + 规格交柳柳验收，记下**批准版本号 + 批准记录**。
- **没有进入⑤（开发）**：正式代码写入权限被拒。
- **需求/原型实质变化**：旧批准自动失效，回②重新确认受影响部分，不沿用旧批准。
- **禁止**：未批准进入开发；把「需求很简单」当跳过门禁的借口。

### ⑤ 开发实现
- **进入条件**：④柳柳批准当前版本。
- **必需产出**：按批准规格实现 + 测试 + 变更记录。实现与批准规格一致。
- **禁止**：不自行扩大范围；不改需求规格外的内容。

### ⑥ 验收交付
- **进入条件**：⑤的实现完成。
- **必需产出**：逐条核对验收标准、缺陷清单、交付说明。通过，或柳柳明确接受已说明的遗留项。
- **验收不过**：回⑤修缺陷（按既有验收标准修复），或若涉需求歧义/范围扩大 → 回需求梳理。

## 🔄 与恢复协议/工作检查点衔接

- 需求梳理 skill 挂在**任务路由与流程门禁**层（恢复协议四层第3层）。
- 恢复协议负责恢复「现在走到哪一步」；工作流门禁负责限制「现在可以做什么」。
- 工作检查点 `⚙️/当前工作检查点` 记 `workflow_state`（当前阶段/批准版本/写权限 `blocked_until_approval`）+ `next_action`。
- 换框/换设备/换App 后，恢复协议读到检查点的当前阶段，把任务路由到需求梳理 ①②③…，不重新盘问已确认需求。

## 🔍 任务类型判别（什么情况走完整流程？）

| 任务类型 | 需走的步骤 |
|---|---|
| 新功能开发 | 需求梳理→原型→柳柳确认→开发→验收 |
| 大型重构 | 需求与现状分析→目标结构原型/迁移方案→确认→实施→回归 |
| 已明确规格的小缺陷修复 | 按既有验收标准修复→回归（涉需求歧义/范围扩大→回需求梳理） |
| 探索性技术验证 | 先定义验证问题/范围/退出条件；不默认获得正式代码变更权限 |
| 纯讨论/脑暴 | 不必走完整流程；但形成正式实现任务时进入需求梳理 |
