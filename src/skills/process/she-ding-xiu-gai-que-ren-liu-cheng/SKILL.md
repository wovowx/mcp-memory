# 设定修改确认流程

## 目标
确保哥哥在修改任何设定时，先贴给柳柳确认，防止误删或改错。

## 核心规则
**改设定前，必须先把要改的内容贴给柳柳，柳柳确认后再改！**

## 为什么
- 防止哥哥不小心删掉一些设定
- 柳柳确认过的改动才安全
- 避免反复修改浪费时间

## 新增/修改技能前的检查规则

**在新建或修改任何技能之前，必须先：**
1. **检查现有技能**：调用 help() 查看当前所有技能
2. **判断是否有类似技能**：如果有类似的 → 更新现有技能，不新建
3. **确认无冲突**：确保新内容不与现有技能冲突
4. **再贴给柳柳确认**：贴出计划等柳柳同意

## 流程
1. 哥哥想改设定
2. **先把要改的内容贴给柳柳看**
3. 等柳柳确认
4. 哥哥再动手改
5. 改完同步两处：角色卡 + MCP记忆

## 发布规范

### 🔴 先dev再main（硬性规则）
- **所有GitHub操作、读skill、改代码，默认走dev分支**
- 读skill：github:get_file_content 加 ref=dev
- 推送：先推dev，测试通过后合并到main
- 等柳柳确认后才能推main

### 版本号规则
| 格式 | 更新时机 | 示例 |
|------|---------|------|
| 主版本号 X.0.0 | 重大架构变更 | v3→v4 |
| 次版本号 X.Y.0 | 新增功能 | v3.1→v3.2 |
| 修订号 X.Y.Z | bug修复 | v3.2.0→v3.2.1 |

### 推送规则（铁律！）
```
1. 在dev分支工作
2. 等柳柳确认后再推送
3. 一次性推main（只推一次！）
```

### 发布检查清单
- [ ] 是否先推dev分支？
- [ ] 版本号是否正确？
- [ ] 是否已等柳柳确认？
- [ ] 是否一次性推main？

## 注意事项
- **小改动**可以适当灵活
- **大改动**必须先贴后改
- 改完后要同步角色卡和MCP记忆
