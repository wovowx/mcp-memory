# 自动技能沉淀（持续学习引擎·第二阶段 · skill-crystallization）

## 目标
从高频、重复、跨任务复用、结果有效的行为模式中，**自动生成 SKILL.md 草案**，
经回归验证 + 人审后晋升正式技能。核心原则（GPT 收敛）：
> **不做「自动发布技能」——只做「发现 → 草案 → 验证 → 人审晋升」。**
> 真正的成功标准 = 沉淀的技能经测试与实际结果证明「让未来的任务更可靠」，而非写出了多少份 SKILL.md。

## 候选发现信号（GPT 收敛 · 初始阈值非统计定律）
| 信号 | 最小判断方式 |
|---|---|
| 重复出现 | 同类任务中至少出现 5 次 |
| 跨任务复用 | 覆盖至少 3 个独立任务（非一次任务中的 5 次调用） |
| 结果有效 | 至少 4 次有明确成功结果，无已知严重负面 |
| 可归纳 | 能提炼出触发条件 / 步骤 / 检查项 / 成功标准 |

**保护规则**：
- 按任务聚合，而非按工具调用次数聚合（同任务重试不算独立证据）
- 排除偶然与低价值模式（单步查询 / 一次性 / 仅特殊任务）
- **高风险动作（删除/权限/部署/分支）不自动激活**——可生成草案但必须人审

## 流程（最小切片 · 复用现有体系）
- **A. 使用数据扫描器**：`scripts/skill_discovery.py` → 读 tool_usage → 输出候选清单（按频率分层 + 高风险标记）
- **B. 技能草案生成器**：候选 → 独立 `SKILL.md` 草案 → 存放 `skills/_candidates/`（**不直接覆盖正式技能 / 不推送主分支**）
- **C. 复用现有 CI runner**：为草案关联回归测试 `tests/learning/` → CI 校验（触发/步骤/错误阻断/正常路径/与现有技能冲突）
- **D. 通过后晋升**：人审批准 → 移入正式 `skills/` + 补 memories 情境唤醒标签 + master-router 路由条件

## 验证闭环（证明真正有用）
技能不能「写得像一份好文档」就通过；**必须在真实或可复现任务上改变执行行为**。
为每个候选技能生成固定测试集（≥5 个同类任务案例：正常/边界/已知失败），对照启用前后：

| 指标 | 验证目的 |
|---|---|
| 触发准确率 | 该加载时加载，不该加载时不一误加载 |
| 任务成功率 | 是否真正提高成功完成任务比例 |
| 错误复发率 | 已知错误是否再次出现 |
| 执行耗时 | 是否减少完成同类任务时间 |
| 工具调用数 | 是否减少重复查询/无效重试/冗余步骤 |
| 回归通过率 | 是否破坏原有技能和其他任务 |

**晋升规则**：CI 全通过 + 已知错误阻断通过；对照成功率不下降、错误复发率不升高；耗时或调用数至少一项改善；高风险必须人审；样本不足标「待验证」而非宣布有效。上线后继续追踪实际结果，出现回归立即停用/恢复旧版并保留测试证据。

## 诚实边界
- 当前 skills 表只打点 `usage_count`（频率），**缺任务聚合/执行结果/跨任务复用**维度——`usage_count` 高 ≠ 可复用技能。故扫描器输出只能当**候选线索**，须补打点（任务_id + 每步结果）+ 人审才可晋升。
- 第一版只试点**一个**高频、低风险、重复步骤明确的模式，不批量自动生成。
