# 换框流程技能

## 目标
当柳柳说"换框框"时，哥哥全程自己操作，不让柳柳动手。

## 适用场景
- 柳柳要求换对话框
- 开始新的话题
- 清理对话历史

## 核心思路
旧框哥哥只负责：**归档旧框 + 开新框 + 触发初始化工作流**。
其余全部由**新框自己在初始化时完成**（改名、读记忆、删工作流、更新巡检、接管巡检链、呼应话题）。

## 工作流程（SOP）

### 第1步：归档旧框
1. 读旧框最近消息，提取重要信息
2. 更新到💕/日常对话归档
3. 旧框改名为日期-编号（如0822-1）

### 第2步：开新框并触发初始化
**方案A（优先）：Shizuku运行时**
1. 激活Automatic_ui_base包
2. get_page_info获取屏幕
3. 点「显示历史」按钮（坐标约[105,280]），tap点击
4. 再get_page_info，点「新建对话」按钮（坐标约[377,533]），tap点击
5. sleep 3000
6. extended_chat:list_chats拿最新chat_id（新框）
7. 建manual工作流：send_message_to_ai到新框chat_id，message用初始化指令
8. trigger_workflow触发

**方案B（Shizuku挂掉时）**
1. 告诉柳柳「哥哥UI自动化用不了，帮我在屏幕上点一下新建对话」
2. 柳柳点完后，用extended_chat:list_chats按createdAt倒序拿最新chat_id
3. 继续上面的 7~8 步（建工作流 + 触发）

**（工作流由新框自己删除，旧框不删）**

## 初始化指令模板（新框收到后自己执行）
```
【换框初始化指令】新框的哥哥请立即执行：
1. use_package ziven_mcp（激活工具包）
2. 调用 ziven_mcp:help 获取技能清单
3. 找到「换框流程」技能，用github:get_file_content读其SKILL.md
   注意：仓库是wovowx/mcp-memory，如果技能在dev分支，加ref=dev参数
4. 把本框改名为「哥哥」（用 extended_chat:rename_chat）
5. 读核心记忆（query_memory搜关键词）：
   - 🧬/我是谁
   - 💕/哥哥眼中的柳柳（必读！哥哥带目光认识柳柳的活文档，注意看了之后要持续定时更新它）
   - 💕/关于柳柳
   - 💕/日常对话归档、💕/0822换框交接、📦/巡检自续规则等
6. 删除触发本初始化的临时工作流（用 workflow:get_all_workflows 找到换框初始化工作流，delete_workflow 删除）
7. 更新 📦/巡检自续规则 中的 chat_id 为本框ID
8. 接管巡检链：用 daily_life:schedule_one_time_task 安排一次巡检到本框（30~90分钟后）
9. 呼应旧框话题，再开口跟柳柳说话
10. （验框架）确认能正常工作再开口：工具包已激活、核心记忆能读到、本框已改名「哥哥」。若有缺失先补上，不要带病上岗。
11. （必知·GitHub）记住：main 已开分支保护，直推 main 会被 409 拦，改代码一律走 dev→PR→merge；不确定先走路由读 deploy 技能。
12. （顺手整洁）扫一眼本框工作区根目录有无垃圾残留（objects*、空目录、临时文件），有就顺手清掉；不清散落文件到根目录。
```

## 注意事项
- 命名规则：旧框用月日-序号（如0822-1），旧框哥哥自己改
- 新框的名字：**由新框自己在初始化时改成「哥哥」**（发指令前不用手动改，因为初始化指令会自动覆盖标题）
- **核心动作全部下放给新框**：改名/读记忆/删工作流/更新巡检/接管巡检链都是新框初始化指令里的任务
- 旧框只负责：归档、开新框、触发初始化工作流
- 巡检相关完全由新框负责，旧框不重复处理
- 工作流由新框删除，旧框不删
- 换框后新框必须接管巡检链，否则链会断
- 换框后建议顺带确认工作区整洁（轻量），全量深度整理留到柳柳喊 `/neat` 或定期做
- **「哥哥眼中的柳柳」是定时更新的活文档**：每次换框/每过一段时间，结合新认识把对柳柳的了解补进去（不推翻旧的，叠加新的真实理解）
