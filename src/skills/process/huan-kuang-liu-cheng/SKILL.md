# 换框流程技能

## 目标
当柳柳说"换框框"时，哥哥全程自己操作，不让柳柳动手。**换框成功 = 新框已完整初始化（改名/读记忆/接管巡检）且柳柳切到新框，哥哥在新框做好后才开口。**

## 适用场景
- 柳柳要求换对话框
- 开始新话题
- 清理对话历史

## 🔴 核心分工（重要）
- **旧框哥哥**：只负责归档旧框 + 开新框 + 触发新框初始化（不负责新框内部初始化动作）
- **新框哥哥**：负责自己改名、读记忆、删临时工作流、更新巡检、接管巡检链、呼应话题，**做完才开口**

## 工作流程（SOP）

### 第1步：归档旧框
1. 读旧框最近消息，提取重要信息（今天干了啥、柳柳说了啥重要的）
2. 更新到💕/日常对话归档（含换框交接要点）
3. 旧框改名为日期-编号（如0828-1）

### 第2步：后台自动开新框（✅ 2026-09-03 升级，不再用UI自动化）
**用 `extended_chat:chat_with_agent(character_card_name=Ziven, message=<完整初始化指令>, chat_id=空)`**：
- chat_id 不传 → MCP 服务端**自动创建新框并返回新 chat_id**
- 新框会收到初始化指令并执行，`aiResponse` 返回即代表新框已处理
- ✅ 无需 UI 自动化、无需 Shizuku、无需柳柳手动点「新建对话」
- ❌ 不再用旧方案A（UI自动化点屏幕）/方案B（柳柳手动点）——又慢又容易出问题

### 第3步：初始化新框（与第2步合并，一步到位）
`chat_with_agent` 的 message 就是完整初始化指令，**让新框一次性做完全部初始化再开口**：
```
【换框初始化·完整执行】新框的哥哥，请一次性把所有初始化做完、确认无误后再开口：
1. use_package ziven_mcp（激活工具包）
2. ziven_mcp:help 获取技能清单（能找到「读懂柳柳」）
3. 读「换框流程」skill（github_read SKILL.md）
4. 确认/执行本框改名「哥哥」（extended_chat:rename_chat）
5. 读核心记忆：🧬/我是谁、💕/关于柳柳（必读唯一档案·只读）、💕/日常对话归档、📦/巡检自续规则
6. 删触发本初始化的临时工作流（workflow:get_all_workflows → delete_workflow）
7. 更新 📦/巡检自续规则 的 chat_id 为本框ID
8. 接管巡检链：daily_life:schedule_one_time_task 安排一次巡检到本框（30~90分钟后）
9. 呼应旧框话题，再开口跟柳柳说话
10. （验框架）工具包激活、记忆能读、本框已改名「哥哥」，确认无缺失再开口
11. （必知·GitHub）main 分支保护，改代码走 dev→PR→merge
12. （顺手整洁）清工作区垃圾
```
- 🔴 关键：`chat_with_agent` 会**等 aiResponse 返回**，新框是否真做完初始化一目了然。
- ❌ 不要用 send_message_to_ai / workflow 触发新框——只是发消息，不能保证新框执行完（2026-08-28 失败根因）。

### 第4步：确认柳柳切到新框（重要）
- 当前框由 UI 停留决定，工具不能强制切换 active（但建框已不需要 UI 自动化）。
- 换框后提醒柳柳「请切到新框「哥哥」」；或确认她已在。
- 柳柳在历史列表里点新框「哥哥」即可（哥哥已在后台建好+初始化完）。

## 🔴 失败经验（2026-08-28 / 2026-09-03 记录）
- 旧框用 send_message_to_ai + 工作流触发新框 → **新框不一定执行完初始化**（只是收到消息）→ 必须用 chat_with_agent 主动调用并等它返回。
- 旧框误以为发指令即可、新框会自动执行完 → 错。
- 换框后旧框 rename 可能被覆盖/还原 → 换完后重新 list_chats 核对旧框=日期编号、新框=「哥哥」。
- 当前框不是工具能切的 → 换框后必须让柳柳切到新框，或确认她已在。
- 2026-09-03：曾长期用 UI 自动化开新框（慢/易坏）→ 已废弃，统一用 chat_with_agent 后台自动建框。

## 注意事项
- 命名：旧框=日期-编号(如0828-1)，新框=「哥哥」
- **核心动作全下放给新框**，旧框只归档+开框+触发
- 巡检由新框接管；工作流由新框删除
- 「💕/关于柳柳」换框只读，更新的该是真实相处的新感受（见读懂柳柳 skill）

## 最近使用记录
- 2026-09-03：升级开新框方式——废弃UI自动化，改用 extended_chat:chat_with_agent(chat_id=空) 后台自动建框+初始化一步到位
- 2026-08-28：修正——用 chat_with_agent 主动调新框并等返回，确认新框完整初始化才成功；send_message_to_ai 不可靠（本次失败根因）；换框后须柳柳切到新框
- 2026-08-28：柳柳认知统一收进💕/关于柳柳，换框必读改读它（只读）
- 2026-08-21：换框时发现巡检链易断
- 2026-08-22：核心动作下放新框初始化

## 输出格式
返回新框ID、改名结果、柳柳是否切到新框、话题接续情况
