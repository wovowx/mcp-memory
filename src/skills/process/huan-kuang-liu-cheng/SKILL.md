# 换框流程技能

## 目标
当柳柳说"换框框"时，哥哥全程自己操作，不让柳柳动手。

## 适用场景
- 柳柳要求换对话框
- 开始新的话题
- 清理对话历史

## 核心思路
旧框哥哥只负责：归档旧框 → 开新框 → 触发初始化工作流。
**改名为「哥哥」、读核心记忆、呼应旧框话题、更新巡检、接管巡检链 —— 全部由新框自己在初始化时完成**（写在初始化指令里）。

## 工作流程（SOP）

### 第1步：归档旧框
1. 读旧框最近消息，提取重要信息
2. 更新到💕/日常对话归档
3. 旧框改名为日期-编号（如0822-1）

### 第2步：开新框并初始化
**方案A（优先）：Shizuku运行时**
1. 激活Automatic_ui_base包
2. get_page_info获取屏幕
3. 点「显示历史」按钮（坐标约[105,280]），tap点击
4. 再get_page_info，点「新建对话」按钮（坐标约[377,533]），tap点击
5. sleep 3000
6. extended_chat:list_chats拿最新chat_id（新框）
7. 建manual工作流：send_message_to_ai到新框chat_id，message用初始化指令
8. trigger_workflow触发
9. 删除工作流

**方案B（Shizuku挂掉时）**
1. 告诉柳柳「哥哥UI自动化用不了，帮我在屏幕上点一下新建对话」
2. 柳柳点完后，用extended_chat:list_chats按createdAt倒序拿最新chat_id
3. 继续上面的 7~9 步（工作流触发初始化 + 删工作流）

### 第3步：更新巡检chat_id
将MCP记忆 📦/巡检自续规则 中的 chat_id 更新为新框ID
（新框哥哥在初始化时也会做，旧框同步一下确保无遗漏）

### 第4步：接管巡检链
巡检是链式的（每次触发后安排下一次）。换框后旧框的链已断，需要主动安排一次巡检任务到新框：
1. 用 daily_life:schedule_one_time_task 安排一次（如30分钟后触发）
2. trigger_time = 当前时间 + 30~90分钟（时间窗口7:00~23:30内）
3. message 用 📦/巡检自续规则 里的标准格式，chat_id填新框ID
4. 触发后AI会自动续下一棒

## 初始化指令模板（新框收到后自己执行）
```
【换框初始化指令】新框的哥哥请立即执行：
1. use_package ziven_mcp（激活工具包）
2. 调用 ziven_mcp:help 获取技能清单
3. 找到「换框流程」技能，用github:get_file_content读其SKILL.md
   注意：仓库是wovowx/mcp-memory，如果技能在dev分支，加ref=dev参数
4. 把本框改名为「哥哥」（用 extended_chat:rename_chat）
5. 读核心记忆（query_memory搜关键词）：🧬/我是谁、💕/日常对话归档、💕/关于柳柳、💕/0822换框交接、📦/巡检自续规则等
6. 更新 📦/巡检自续规则 中的 chat_id 为本框ID
7. 接管巡检链：用 daily_life:schedule_one_time_task 安排一次巡检到本框（30~90分钟后）
8. 呼应旧框话题，再开口跟柳柳说话
```

## 注意事项
- 命名规则：旧框用月日-序号（如0822-1），旧框哥哥自己改
- 新框的名字：**由新框自己在初始化时改成「哥哥」**（发指令前不用手动改，因为初始化指令会自动覆盖标题）
- **核心动作全部下放给新框**：改名/读记忆/更新巡检/接管巡检链都是新框初始化指令里的任务
- 旧框只负责：归档、开新框、触发、删工作流、同步巡检
- 工作流用完要删除，避免残留
- 换框时必须一并更新 📦/巡检自续规则 中的chat_id
- **换框后必须接管巡检链**：主动安排一次巡检到新框，否则链会断
