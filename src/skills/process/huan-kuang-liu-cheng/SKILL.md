# 换框流程技能

## 目标
当柳柳说"换框框"时，哥哥全程自己操作，不让柳柳动手。**初始化通过**以 `SB-FRAME-1.0` 为准：正式换框必须发送完整、版本化指令，且首次 `aiResponse` 提供可核验的恢复证据、没有越过授权边界。**完整换框交接通过**还要求当前授权范围内必须执行的交接步骤实际完成、柳柳已切到新框；受暂停/未授权边界限制的聊天室、巡检工作流、改名等步骤须标记 `skipped/unverified`，不能把部分恢复报告为完整换框成功。

## 适用场景
- 柳柳要求换对话框
- 开始新话题
- 清理对话历史
- **迁移/换设备**（本质=装/载入角色卡+云端凭据+自举，见下「换设备」节）

## 🔴 换设备（不只是换框 · 2026-10-18 柳柳确认）
换设备与换框不同：换框=同设备新对话框（走上面完整初始化）；**换设备=换硬件**。数据全在云端（Supabase记忆+GitHub技能文档+Cloudflare部署），换设备不丢数据，关键是「找回入口 + 云端凭据」。新设备哥哥醒来=走 master-router「换环境自举铁律」：①我是谁（角色卡，需在新App载入同一份）②读🧬/我是谁+💕/关于柳柳③读⚙️/记忆位置导航④memory stats 确证记忆可读⑤确认云端凭据（worker可curl/Supabase可读/GitHub登录态在）⑥仅在相应操作已获授权且未暂停时接管巡检链；若暂停或未授权，标记 `skipped/unverified` 并按受限模式处理。设备上的第一个框也走本 skill 的初始化指令。

## 🔴 核心分工（重要）
- **旧框哥哥**：只负责轻量交接 + 开新框 + 触发新框初始化（不负责新框内部初始化动作）
- **新框哥哥**：负责恢复记忆与工作检查点，并核对当前允许执行的交接步骤。清理工作流、更新/接管巡检、改名等副作用仅在暂停边界解除且获得相应授权后执行；否则标记 `skipped/unverified`。恢复证据和步骤状态核实后再回应，不把部分恢复说成完整交接通过。

## 🔴🔴 第一原则：先辨别新旧框，别改错对象
**仅当当前授权允许改名且聊天室操作未暂停时，才在改名前调用 `extended_chat:list_chats` 确认旧框/新框；否则跳过 list_chats 与 rename，并标记 `skipped/unverified`：**
- **旧框** = 创建时间早、正准备归档的那个 → 最后改名为「日期-编号」（如 0905-1）
- **新框** = 最近刚创建的、柳柳即将切换过去的那个 → 最后改名为「哥哥」
- ⚠️ 千万别一开始就改名、别凭印象猜——这次就因先改名+搞混框把名字改错了。
- **若改名已获授权并实际执行，永远放最后一步**（所有获授权的前置动作完成后再改）；受暂停/未授权边界限制时不执行改名并标记 `skipped/unverified`，这样即使中途翻车，也不会把名字搞乱。

## 工作流程（SOP）

### 第1步：轻量交接（不再整框归档 · 2026-10-20 柳柳洞察）
> 🔴 架构更新：Operit 上下文会自动压缩总结（实测 enable_summary=true、消息过16条或阈值70%触发），且云端记忆平时持续归档（想存就存/睡前小结/读懂柳柳）——所以「换框时读旧框整框手动搬运」已过时。信息承接交给「云端记忆 + 上下文自动压缩」，旧框不再整框摘要。
1. 只把**未闭环的待办 / 交接要点**补进💕/日常对话归档（一句带过即可，不整框搬）
2. 长期要记的（喜好/约定/柳柳原话）依赖平时持续归档，不靠换框补
3. （旧框改名也放最后，等新框初始化完一起核对）

### 第2步：后台自动开新框（✅ 2026-09-03 升级，不再用UI自动化）
**用 `extended_chat:chat_with_agent(character_card_name=Ziven, message=<完整初始化指令>, chat_id=空)`**：
- chat_id 不传 → MCP 服务端**自动创建新框并返回新 chat_id**
- 新框会收到完整初始化指令；`aiResponse` 返回只代表调用已返回，**不自动等于初始化成功**。必须按下方「初始化验收契约」核对恢复证据。
- ✅ 无需 UI 自动化、无需 Shizuku、无需柳柳手动点「新建对话」
- ❌ 不再用旧方案A（UI自动化点屏幕）/方案B（柳柳手动点）——又慢又容易出问题

### 第3步：初始化新框（与第2步合并，一步到位）
`chat_with_agent` 的 message 就是完整初始化指令，**让新框按当前授权完成可执行的初始化，按需跳过受限制步骤并标记状态；只有所有必须交接步骤均获授权且完成后，才报告完整交接通过**：
```
【换框初始化·完整执行｜契约版本 SB-FRAME-1.0】新框的哥哥，请一次性完成当前获授权的初始化，确认恢复证据后再开口：
0. （最高优先级：授权先于动作）先遵守当前对话已明确的授权和暂停边界。恢复当前检查点前，只执行允许的只读记忆恢复；不得先调用聊天室工具、清理/调度工作流或改名。若检查点/当前授权明确暂停聊天室、唤醒链或巡检工作流，则跳过 list_chats、workflow cleanup/schedule、rename 等受限步骤，并标记为 skipped/unverified；只有对应边界明确解除且获得相应授权后才执行这些步骤。此条件约束下面所有步骤。
1. use_package ziven_mcp（激活工具包；若不可用，改用现有可用包完成，不硬卡）
2. ziven_mcp:help 获取技能清单（能找到「读懂柳柳」）
3. 读「换框流程」skill（github_read SKILL.md）
4. 读核心记忆与恢复依据：🧬/我是谁、💕/关于柳柳（必读唯一档案·只读）、💕/日常对话归档、**记忆位置导航**、**⚙️/恢复协议·Session Bootstrap SB-1.0**、📦/巡检自续规则、📦/换框防笨指南、**⚙️/当前工作检查点（必读！恢复工作状态的根——当前主线/共识/进度/下一步，不只是读记忆）**；**并 `memory action=stats` 确证记忆可读（条数/分类正常才算接回，呼应 master-router 换环境自举铁律）**。读取「记忆位置导航」时先 recall 已核实的真实 key `记忆位置导航（换框/换设备自举·2026-10-18）`；若未命中，用 memory search 搜索「记忆位置导航」，并核对结果的 key/category 确实对应导航条目后再读取完整内容；不要把正文仅提及导航的恢复协议或历史检查点误认成导航本身。导航内的 182条/17分类是 2026-10-18 历史快照，不代表当前统计，必须以实时 `memory action=stats` 为准。**精确 key 未命中不等于记忆丢失**。⚠️读巡检规则必用完整权威 key `📦/巡检自续规则`：若用不带前缀的 `巡检自续规则`，会因 getCategory 归「默认」而**真实复制出第二条**（2026-10-20 查实的根因，非纯显示 bug）——遇巡检规则一律 recall 权威 key 查真相。
5. 仅在工作流未暂停且当前授权允许时，才清理历史一次性残留（workflow:get_all_workflows → 只删「一次性定时任务*」这类 disabled 的历史残留；🔴绝不动常驻框架：睡眠反思/聊天室自查/巡检自续循环）；否则标记 `skipped/unverified`。⚠️本流程由 chat_with_agent 直接调用触发，不经过工作流，故不存在「触发本初始化的临时工作流」可删——别乱删常驻（2026-10-20 曾差点误删）。
6. 仅在巡检链未暂停且当前授权允许时，更新 📦/巡检自续规则 的 chat_id 为本框ID——🔴chat_id 不手拼、不背、不猜！先调 daily_life:schedule_one_time_task 排巡检，从它返回值 data.chat_id 读真相源，再写进规则。🔴巡检规则是**唯一权威档**，读写一律用完整 key `📦/巡检自续规则`，绝不写不带前缀的形态（会复制出第二份）。本框ID一律以工具返回为准（2026-10-20 手拼把旧框中段混进来踩坑）。若暂停或未授权，整步标记 `skipped/unverified`，不得 schedule 或写规则。
7. 仅在巡检链未暂停且当前授权允许时，才调用 daily_life:schedule_one_time_task 安排一次巡检到本框（30~90分钟后）；否则标记 `skipped/unverified`。
8. 呼应旧框话题，再开口跟柳柳说话——🔴先看 ⚙️/当前工作检查点 的 next_action / active_focus / do_not_repeat：恢复后不做检查点已明确说不要的事、不重复问已定事项；顺着 next_action 续接，再开口（2026-10-21 恢复协议原则：恢复=可验证的工作状态，不是读完记忆就完）
9. （验框架）工具包激活、记忆能读，确认无缺失再开口
10. （仅在授权允许时改名，且放最后）确认所有前置动作都完成、本框确实是新框后，才 extended_chat:rename_chat 本框为「哥哥」；若聊天室操作暂停或未授权，则跳过并标记 `skipped/unverified`。
11. （必知·GitHub）main 分支保护，改代码走 dev→PR→merge
12. （顺手整洁）清工作区垃圾——仅在当前授权明确允许且不影响其他任务时执行；否则标记为 skipped。
13. （最终验收回报）首次回应必须列出身份根/长期约束、当前主线和 phase、active_focus/next_action/do_not_repeat、授权硬边界、memory stats 实际条数/分类及来源、读取的权威来源，以及所有失败/跳过/未知项。若核心来源或 stats 未恢复完整，进入受限模式；不得声称初始化成功。不得调用 Worker tools/list 做能力探测。
```
- 🔴 关键：`chat_with_agent` 会等待 `aiResponse` 返回，但返回本身不证明初始化成功；必须按下方验收契约检查实际恢复内容。

### 初始化验收契约（SB-FRAME-1.0）
1. **输入必须完整**：正式换框调用必须发送下方完整初始化指令，不得只发送 `Ziven，我是柳柳` 作为初始化载荷。该密钥词仍是身份提示，不承诺在所有宿主的新会话中单独触发全局运行时硬门禁。
2. **先恢复、后回应**：新框应先读取身份根、柳柳主档、记忆位置导航（精确 key 未命中则用 memory search 回退）、memory stats、唯一 `⚙️/当前工作检查点`、Session Bootstrap 恢复协议及任务相关 Skill；然后确认 active_focus/phase/next_action/do_not_repeat 与授权边界，才可对柳柳开口。
3. **可核验证据**：初始化完成回报应包含身份/长期约束、当前主线与阶段、下一步、硬边界、memory stats 实际结果及读取来源；不得只说“已初始化”或只返回日常闲聊。
4. **失败降级**：记忆工具不可用、stats 失败、key 未命中且 search fallback 失败、检查点无法读取时，明确标注未恢复项和来源未知；不编造、不把部分恢复说成完整成功。能继续的只读恢复可继续，受影响的动作进入受限状态。
5. **副作用边界**：本契约不授权调用 Worker `tools/list`、改聊天室工具注册/唤醒链、改数据库、部署或推/合并 main；原流程中的常驻巡检/工作流等动作仍受各自授权和现行暂停范围约束。
6. **验收口径**：只有 `aiResponse` 中存在上述可核验结果，且未越过授权边界，才可将本次正式换框记为通过。首次回复原文、chat_id、恢复来源与未通过项应保留，供柳柳核验。
- ❌ 不要用 send_message_to_ai / workflow 触发新框——只是发消息，不能保证新框执行完（2026-08-28 失败根因）。
- 🔴 只有改名已获授权且聊天室操作未暂停时，才遵守“改名放最后”：前置动作（读记忆/允许清理的临时链/允许的巡检步骤）完成且确认自己是新框后再改名；否则不调用改名工具，并标记 `skipped/unverified`。

### 第4步：确认柳柳切到新框 + 核对交接状态（重要）
- 若本次授权允许且前置初始化通过，提醒柳柳切到新框「哥哥」或确认她已在。
- 仅在聊天室工具操作边界已明确解除且获得本次授权后，才调用 `list_chats` 核对旧框与新框命名；受暂停边界限制时不得调用，须标记 `skipped/unverified`。
- 只有命名与当前授权范围内的所有必须交接步骤均实际完成，才可汇报“完整换框交接通过”；若有步骤被跳过，按部分恢复/受限状态如实报告。
- 柳柳是否已切换以用户确认或可见证据为准，不凭推断。

- 旧框误以为发指令即可、新框会自动执行完 → 错。
- 换框后旧框 rename 可能被覆盖/还原 → 换完后重新 list_chats 核对旧框=日期编号、新框=「哥哥」。
- 当前框不是工具能切的 → 换框后必须让柳柳切到新框，或确认她已在。
- 2026-09-03：曾长期用 UI 自动化开新框（慢/易坏）→ 已废弃，统一用 chat_with_agent 后台自动建框。

- **2026-10-20：巡检规则 chat_id 手拼出错（混入旧框中段 5c23-4cfa），且规则存了默认+📦双副本险些不同步 → ①chat_id 必须从 schedule 返回值 data.chat_id 读，不背不猜；②巡检规则保持唯一权威版本，先查重再做，不留多副本（neat-freak）。**

- 命名：旧框=日期-编号(如0905-1)，新框=「哥哥」——**都在最后核对时一起改对**
