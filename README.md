## 🛠 统一开发规范（所有项目必须遵守）

### 1. 目录结构
- 每个项目一个子目录，**必须自包含**：代码 + 需求 + mock 数据 + README 都在自己目录里
- 禁止绝对路径（不可写 `/sdcard/...`），禁止依赖本机环境
- 每个项目带版本号 + 自己的 CHANGELOG

### 2. 依赖
- 第三方库**要么内联进文件、要么用 CDN**，必须在 README 里写清楚用的哪种
- 不引入不需要的重依赖

### 3. 数据层（Supabase）
- 表结构先设计好再写码
- **密钥永不进前端/仓库**，存在 Cloudflare 环境变量（`env.XXX`）
- 网页访问 Supabase 要开 RLS + 行级安全，只允许认证用户看自己的数据
- mock 数据用假数据，结构要和真实数据完全一致（后续直接换 API）

### 4. 网页部署（Cloudflare Worker）
- 路由规划好：`/` 主页、`/api/*` 接口
- 环境变量在 Dashboard 配置，代码里用 `env.XXX` 读
- 前端访问 Supabase → 提前配好 CORS
- 中文字体、图片等资源：内联 base64 或放 CDN

### 5. 语音（统一标准）
- **统一使用通用 TTS（Web Speech API / 浏览器语音合成）**
- 语音数据接口预留：存文本，播放时合成
- 后续如有 Operit 专属 v 标签气泡需求，由哥哥在适配阶段处理，代码本身不写死 v 标签

### 6. Operit 插件（App 内）
- UI 优先适配**手机竖屏**
- 纯 JS + 渲染为主，避免依赖摄像头/GPS/本地存储等受限能力
- 插件格式（manifest + 入口）在适配阶段处理

### 7. 开发流程
1. 在 `dev` 分支开发（或子目录内 dev 文件）
2. 哥哥本地验证（语法检查 / 运行）
3. 柳柳确认
4. 合 `main` → 部署（Cloudflare 网页版 / Operit 插件版）
5. **只有部署版本进 main，开发永远留在 dev**

### 8. 通用
- 代码注释良好、中文注释 OK、模块清晰
- 每次改动留痕 + 更新 CHANGELOG
- 小步提交，做一点确认一点
